# @outloud/model 2.0

Upgrades a project from @outloud/model 1.x. `hasOne` and `hasMany` become one
`relation` decorator; `map` and `mapper` become `fromJSON`, `fromArray`,
`mapperJSON` and `mapperArray`; `compose`, `fill` and `serialize` are removed;
and the package is ES modules only. Most projects need steps 1 to 4; step 5 is
optional.

## Changes

- `map()` and `mapper()` are removed. `fromJSON()` accepts `null` and
  `undefined` and returns `null` for them, as `map()` did. `fromArray()` maps
  an array and returns `[]` for `null` and `undefined`. `mapperJSON()` and
  `mapperArray()` return functions doing the same.
- `fromJSON()` no longer takes the first item of an array, and `fromArray()`
  doesn't wrap a single object, as `map(data, false)` and `map(data, true)` did.
- `@relation(() => Model)` and `@relation(() => Model, { many: true })` replace
  `@hasOne` and `@hasMany`, which stay as deprecated aliases. A relationship
  maps `null` and `undefined` to `null`, or `[]` with `many`, as before, but no
  longer takes the first item of an array or wraps a single object.
- `compose()` is removed. Mixins apply by wrapping the class.
- `fill()` is removed; `merge()` does the same. `serialize()` is removed;
  `toJSON()` returns the same data, and a custom serialization overrides
  `toJSON()`. `$attributes`, always empty, is removed.
- `merge()`, and so `create()` and `fromJSON()`, skip data for a property that
  only has a getter on the model, which threw a `TypeError` before.
- `column.date()` reads `YYYY-MM-DD` as midnight in local time instead of UTC,
  so the day no longer shifts back west of UTC.
- No CommonJS build. Node.js 20 or later.

New, no change needed: `Model.typed<Data>()` and `TypedMethod`, to type a model
from a generated API type; `Model.column` and `Model.relation`; and the
`NormalizedModel`, `ModelValues` and other types, exported as in 1.x.

## Steps

Find the models first:

    grep -rnE "from '@outloud/model'" --include='*.ts' --include='*.tsx' --include='*.vue' --exclude-dir=node_modules .

Check the installed version in `package.json`. Projects on 0.x use `toModel`,
`create` for API data and `compose`; upgrade them to 1.x first, or apply the
steps below to their 0.x calls as well.

### 1. Replace `map()` and `mapper()`

**Check:** `grep -rnE '\b[A-Z][A-Za-z0-9]*\.(map|mapper)\(' --include='*.ts' --include='*.tsx' --include='*.vue' --exclude-dir=node_modules .` and keep the calls on a model class. Skip when none are.

Before:

    const user = User.map(data)
    const users = User.map(list, true)
    const owner = User.map(response, false)

    useAsyncData('users', () => api.$get('/users'), { transform: User.mapper('array') })
    $useList({ model: Task.mapper('model') })

After:

    const user = User.fromJSON(data)
    const users = User.fromArray(list)
    const owner = User.fromJSON(response)

    useAsyncData('users', () => api.$get('/users'), { transform: User.mapperArray() })
    $useList({ model: Task.mapperJSON() })

`User.map(data)` on an array becomes `User.fromArray(data)`; read the type of
`data` to tell. `mapper('model')` and `mapper('nullable')` both become
`mapperJSON()`. Where `map(data, true)` received a single object or
`map(data, false)` an array, fix the data or map it explicitly, e.g.
`User.fromArray([data])` or `User.fromJSON(list[0])`.

### 2. Replace `@hasOne` and `@hasMany`

**Check:** `grep -rnE "\b(hasOne|hasMany)\b" --include='*.ts' --include='*.tsx' --include='*.vue' --exclude-dir=node_modules .`. Skip when nothing matches. They still work, so this step can follow later, but do it while upgrading.

Before:

    import { Model, hasMany, hasOne } from '@outloud/model'

    @hasOne(() => Role)
    declare role: Role | null

    @hasMany(() => Comment)
    declare comments: Comment[]

After:

    import { Model, relation } from '@outloud/model'

    @relation(() => Role)
    declare role: Role | null

    @relation(() => Comment, { many: true })
    declare comments: Comment[]

### 3. Replace `fill()`, `serialize()` and `$attributes`

**Check:** `grep -rnE '\.(fill|serialize)\(|\$attributes|^\s*serialize\(' --include='*.ts' --include='*.tsx' --include='*.vue' --exclude-dir=node_modules .` and keep calls on models and model classes that override `serialize()`. Skip when none are.

Before:

    user.fill(values)
    const data = user.serialize()

    class Point extends Model {
      serialize() {
        return { ...super.serialize(), kind: 'point' }
      }
    }

After:

    user.merge(values)
    const data = user.toJSON()

    class Point extends Model {
      toJSON() {
        return { ...super.toJSON(), kind: 'point' }
      }
    }

### 4. Replace `compose()`

**Check:** `grep -rnE "\bcompose\(" --include='*.ts' --include='*.tsx' --include='*.vue' --exclude-dir=node_modules .`. Skip when nothing matches.

Before:

    import { Model, compose } from '@outloud/model'

    class Post extends compose(Model).with(Timestamps, SoftDeletes) {}

After:

    import { Model } from '@outloud/model'

    class Post extends SoftDeletes(Timestamps(Model)) {}

The innermost mixin is the first of `with()`. The mixins themselves don't
change.

### 5. Optional: type models from generated API types

**Check:** `grep -rlE 'no-unsafe-declaration-merging' --include='*.ts' --exclude-dir=node_modules .` and keep the files where an interface with the data's type is merged into a model class. Skip when none are.

Before:

    /* eslint-disable @typescript-eslint/no-unsafe-declaration-merging */
    export interface Provider extends ProviderData {}

    export class Provider extends Model {}

After:

    export class Provider extends Model.typed<ProviderData>() {}

Remove the lint comment along with the interface.

Leave out of `Data`, with `Omit`, the properties the model declares with
another type, such as dates the model converts to `Date` and relationships. A
subclass of a base class passes it, `RestModel.typed<Data, typeof RestModel>()`,
or the base class declares `declare static typed: TypedMethod<typeof RestModel>`.

## Verify

- `pnpm typecheck` passes.
- The searches of steps 1 to 4 find no `map`, `mapper`, `hasOne`, `hasMany`,
  `fill`, `serialize` or `compose` call on a model.
- Nothing `require()`s `@outloud/model`.
- The project's tests pass.
