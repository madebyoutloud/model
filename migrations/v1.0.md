# @outloud/model 1.0

Upgrades a project from @outloud/model 0.x. `toModel()` becomes `Model.map()`;
the `related` and `collection` aliases are removed; and date columns return
`Date` instead of Day.js unless `configure()` sets it back. Most projects need
steps 1 to 4; steps 5 and 6 are checks, and step 7 is optional.

## Changes

- `toModel()` is removed. `Model.map(data, toArray?)` replaces it, called on
  the model class. `Model.fromJSON()` and `Model.mapper()` are new.
- `map(data, true)` returns `[]` for `null` and `undefined` and wraps a single
  object in an array, where `toModel(data, Model, true)` threw. `map(data,
  false)` takes the first item of an array, where `toModel(data, Model, false)`
  threw. `map()` returns `null` for `undefined` instead of `undefined`, and
  always returns a new array.
- `related` and `collection` are removed. `hasOne` and `hasMany`, which they
  were aliases of, stay. The `relation` decorator of 0.1.0 is removed as well.
- Relationships map like `map()`. A `hasMany` property gets `[]` for `null` and
  wraps a single object, which threw before. A `hasOne` property gets `null` for
  `undefined` and takes the first item of an array, which threw before.
- `column.date()` and `column.dateTime()` return `Date` instead of Day.js.
  `configure()` sets another date type, such as Day.js. `dayjs` is no longer a
  peer dependency. The decorators no longer check the property's type, so
  TypeScript doesn't report a property still declared as `Dayjs`.
- Date strings are parsed with `new Date()` first, so a string it can't read
  becomes an invalid date. ISO 8601 strings are fine. `column.date()` reads
  `YYYY-MM-DD` as midnight UTC, where Day.js read it as local midnight, so west
  of UTC the day shifts back by one.
- The `DateColumnDecorator` and `DateTimeColumnDecorator` types are removed.
  `ColumnDecorator` types both decorators.
- Decorators still need `experimentalDecorators`. 1.x works with
  `useDefineForClassFields` on or off.
- The build targets ES2022 and keeps the CommonJS build.

Unchanged: `create()`, `fill()`, `merge()`, `serialize()`, `toJSON()`,
`clone()`, `compose()`, `$boot()`, `$addColumn()`, `NormalizedModel`,
`ModelClass`, `ModelValues` and `DecoratorFn`. 2.0 removes some of them; leave
them for its guide.

New, no change needed: `column.extend()` and the `Column` interface, to add
custom column decorators.

## Steps

Find the models first:

    grep -rnE "from '@outloud/model'" --include='*.ts' --include='*.tsx' --include='*.vue' --exclude-dir=node_modules .

Check the installed version in `package.json`. Projects already on 1.x skip
this guide and go on to `v2.0.md`.

### 1. Update the package

**Check:** `grep -n '@outloud/model' package.json`. The version is `0.x` or a
`file:` reference to a local tarball or folder.

Before:

    "@outloud/model": "^0.1.2"
    "@outloud/model": "file:vendor/outloud-model-0.1.3.tgz"

After:

    "@outloud/model": "^1.0.5"

Use 1.0.5 or later; earlier 1.0 releases have bugs in dates and relationships.
Install it with the project's package manager so the lockfile updates. A local
tarball of 0.x is no longer needed after this.

If step 4 applies, keep `dayjs` in `dependencies`. 0.x listed it as a peer
dependency; 1.x doesn't.

### 2. Replace `toModel()`

**Check:** `grep -rnE '\btoModel\b' --include='*.ts' --include='*.tsx' --include='*.vue' --exclude-dir=node_modules .` and keep the calls imported from `@outloud/model`. Skip when none are.

Before:

    import { toModel } from '@outloud/model'

    const user = toModel(data, User)
    const users = toModel(list, User, true)
    const owner = toModel(response, User, false)

    useAsyncData('users', () => api.$get('/users'), {
      transform: (data) => toModel(data, User, true),
    })

    function hydrate<T extends ModelClass>(value: object | object[] | null, model: T) {
      return toModel(value, model)
    }

After:

    const user = User.map(data)
    const users = User.map(list, true)
    const owner = User.map(response, false)

    useAsyncData('users', () => api.$get('/users'), {
      transform: (data) => User.map(data, true),
    })

    function hydrate<T extends ModelClass>(value: object | object[] | null, model: T) {
      return model.map(value)
    }

Keep the third argument as it is. Remove `toModel` from the import, and the
import when nothing else is left in it. `map()` returns a model or an array
already mapped as it is, item by item, as `toModel()` did.

`map()` no longer throws for data of the wrong shape. Look at a `try` around a
`toModel()` call, or code that relies on `undefined`, and adapt it by hand.

### 3. Replace `related` and `collection`

**Check:** `grep -rnE '@(related|collection|relation)\(' --include='*.ts' --include='*.tsx' --include='*.vue' --exclude-dir=node_modules .`. Skip when nothing matches.

Before:

    import { Model, collection, related } from '@outloud/model'

    class Post extends Model {
      @related(() => User)
      author: User | null

      @collection(() => Comment)
      comments: Comment[]
    }

After:

    import { Model, hasMany, hasOne } from '@outloud/model'

    class Post extends Model {
      @hasOne(() => User)
      author: User | null

      @hasMany(() => Comment)
      comments: Comment[]
    }

`related` becomes `hasOne` and `collection` becomes `hasMany`. Change the
imports too; a model may already import `hasOne` or `hasMany`. For `relation`
from 0.1.0, use `hasMany` when the property is an array and `hasOne`
otherwise. Leave the properties as they are. The 2.0 guide replaces `hasOne`
and `hasMany` in turn.

### 4. Keep Day.js dates with `configure()`

**Check:** `grep -rnE 'column\.(date|dateTime)\(' --include='*.ts' --include='*.tsx' --include='*.vue' --exclude-dir=node_modules .`. Skip when nothing matches.

0.x always returned Day.js for these columns, so the code using them calls
Day.js methods such as `format()`. TypeScript doesn't catch the change, so do
this step even when the typecheck passes.

Before:

    import type { Dayjs } from 'dayjs'
    import { Model, column } from '@outloud/model'

    class User extends Model {
      @column.dateTime()
      createdAt: Dayjs
    }

After, with the model unchanged:

    import dayjs, { type Dayjs } from 'dayjs'
    import { configure } from '@outloud/model'

    configure({
      date: {
        deserialize: (value: Date) => dayjs(value),
        serialize: (value: Dayjs) => value.toDate(),
      },
    })

Call `configure()` once, before any model is created: in the app's entry file,
or in a Nuxt app in a plugin such as `plugins/model.ts`, inside
`defineNuxtPlugin()`. Keep the Day.js plugins and locale the app sets up.

A column with its own `deserialize` option keeps it. Its `toJSON()` output
still goes through `configure()`.

Moving the dates to `Date` instead is not mechanical. It needs every Day.js call
on these properties rewritten, so leave it out of this upgrade.

### 5. Replace removed types

**Check:** `grep -rnE '\b(DateColumnDecorator|DateTimeColumnDecorator)\b' --include='*.ts' --include='*.tsx' --include='*.vue' --exclude-dir=node_modules .`. Skip when nothing matches.

Before:

    import type { DateColumnDecorator } from '@outloud/model'

After:

    import type { ColumnDecorator } from '@outloud/model'

### 6. Check the TypeScript settings

**Check:** `grep -rnE 'experimentalDecorators|useDefineForClassFields' --include='tsconfig*.json' --include='nuxt.config.*' --exclude-dir=node_modules .`.

`experimentalDecorators` must stay `true`, in `tsconfig.json` or, in a Nuxt
app, in `typescript.tsConfig.compilerOptions` of `nuxt.config.ts`. Add it when
it's missing. Keep any `vite.esbuild.tsconfigRaw` setting the project has.

Leave `useDefineForClassFields` as it is. A project that sets it to `false`
usually declares plain model properties such as `id: string`, some redeclared
in a subclass with `override`. Without the setting, TypeScript reports the
redeclared ones. Step 7 removes the need for it.

### 7. Optional: declare model properties with `declare`

**Check:** step 6 found `"useDefineForClassFields": false`, and `grep -nE '^\s*(@.*\)\s+)?(public |override )*[a-zA-Z_$][a-zA-Z0-9_$]*[?!]?: '` on the model files found above finds plain properties in model classes and mixins, not in interfaces. Skip when it doesn't. This step can wait.

Before:

    class Client extends APIModel {
      override id: string
      name: string | null

      @hasOne(() => Agent)
      agent?: Agent

      contacts: Contact[] = []
    }

After:

    class Client extends APIModel {
      declare id: string
      declare name: string | null

      @hasOne(() => Agent)
      declare agent?: Agent

      contacts: Contact[] = []
    }

Add `declare` to every property without an initializer, decorated ones too, in
every model and mixin. With the decorator on the same line, `declare` goes after
it: `@hasOne(() => Agent) declare agent?: Agent`. Drop `override`, which can't
be combined with `declare`.
Keep properties with an initializer as they are. Then remove
`"useDefineForClassFields": false`.

## Verify

- `pnpm typecheck` passes.
- `package.json` has `@outloud/model` 1.0.5 or later, and the lockfile matches.
- The searches of steps 2, 3 and 5 find no `toModel`, `related`, `collection`,
  `relation`, `DateColumnDecorator` or `DateTimeColumnDecorator`.
- When step 4 applied, a page that shows a model's date still shows it. Day.js
  methods on dates fail only at runtime.
- The project's tests pass.

To go on to 2.0, follow `v2.0.md` next.
