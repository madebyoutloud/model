# Upgrade to 2.0

2.0 replaces the relationship decorators and the mapping methods with simpler ones, drops `compose`, `fill` and `serialize`, and ships ES modules only.

## Relationships

`hasOne` and `hasMany` still work in 2.0 but are deprecated. Replace them with `relation`:

```ts
// 1.x
@hasOne(() => Role)
declare role: Role | null

@hasMany(() => Comment)
declare comments: Comment[]

// 2.0
@relation(() => Role)
declare role: Role | null

@relation(() => Comment, { many: true })
declare comments: Comment[]
```

`null` and `undefined` still become `null`, or an empty array with `many`. What changed:

- A one-to-one relationship no longer takes the first item when the data is an array.
- A one-to-many relationship no longer wraps a single object in an array.

Fix the data, or map it yourself, where an API relied on that.

## Mapping

`fromJSON` stays. `map` and `mapper` are removed:

| 1.x | 2.0 |
| --- | --- |
| `User.map(data)` with an object | `User.fromJSON(data)` |
| `User.map(data)` with an array | `User.fromArray(data)` |
| `User.map(data)` with `null` | `User.fromJSON(data)`, returns `null` |
| `User.map(data, true)` | `User.fromArray(data)`, after wrapping a single object yourself; `null` returns `[]` |
| `User.map(data, false)` | `User.fromJSON(data)` |
| `User.mapper('array')` | `User.mapperArray()` |
| `User.mapper('model')` | `User.mapperJSON()` |
| `User.mapper('nullable')` | `User.mapperJSON()` |

`null` and `undefined` work as with `map`: `fromJSON` returns `null` and `fromArray` an empty array. So a `map()` call on an object, or on data that may be `null`, becomes `fromJSON()` as it is.

## Composition

`compose` is removed. Apply mixins by wrapping the class. The mixins themselves stay the same, typed with `NormalizedModel`:

```ts
// 1.x
class Post extends compose(Model).with(Timestamps, SoftDeletes) {}

// 2.0
class Post extends SoftDeletes(Timestamps(Model)) {}
```

Mixins apply from the inside out, so the order matches `with()`.

## Instance methods

| 1.x | 2.0 |
| --- | --- |
| `user.fill(values)` | `user.merge(values)`, which `fill` always did |
| `user.serialize()` | `user.toJSON()` |

A custom serialization overrides `toJSON()` instead of `serialize()`.

## Behaviour changes

- Data for a property that only has a getter on the model is skipped. In 1.x, assigning it threw a `TypeError`.
- `column.date()` reads `YYYY-MM-DD` as midnight in local time. In 1.x it read it as UTC midnight, which is the day before west of UTC.
- The `$attributes` property is removed. It was always empty.

## ES modules only

The package no longer ships a CommonJS build. Projects and tools that `require('@outloud/model')` need to import it instead.
