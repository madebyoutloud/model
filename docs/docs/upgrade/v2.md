# Upgrade to 2.0

2.0 replaces the relationship decorators and the mapping methods with simpler ones, and drops `compose`.

## Relationships

`hasOne` and `hasMany` still work in 2.0 but are deprecated. Replace them with `relation`:

```ts
// 1.x
@hasOne(() => Role)
declare role: Role | null

@hasMany(() => Comment)
declare comments: Comment[]

// 2.0
@relation(() => Role)
declare role: Role | null

@relation(() => Comment, { many: true })
declare comments: Comment[]
```

`null` and `undefined` still become `null`, or an empty array with `many`. What changed:

- A one-to-one relationship no longer takes the first item when the data is an array.
- A one-to-many relationship no longer wraps a single object in an array.

Fix the data, or map it yourself, where an API relied on that.

## Mapping

`fromJSON` stays. `map` and `mapper` are removed:

| 1.x | 2.0 |
| --- | --- |
| `User.map(data)` with an object | `User.fromJSON(data)` |
| `User.map(data)` with an array | `User.fromArray(data)` |
| `User.map(data)` with `null` | `data ? User.fromJSON(data) : null` |
| `User.map(data, true)` | `User.fromArray(data)`, after wrapping a single object yourself |
| `User.map(data, false)` | `User.fromJSON(data)` |
| `User.mapper('array')` | `User.mapperArray()` |
| `User.mapper('model')` | `User.mapperJSON()` |
| `User.mapper('nullable')` | `data => data ? User.fromJSON(data) : null` |

`fromJSON` and `fromArray` throw on `null`, where `map` returned `null`. Check what the API can return.

## Composition

`compose` is removed. Apply mixins by wrapping the class. The mixins themselves stay the same, typed with `NormalizedModel`:

```ts
// 1.x
class Post extends compose(Model).with(Timestamps, SoftDeletes) {}

// 2.0
class Post extends SoftDeletes(Timestamps(Model)) {}
```

Mixins apply from the inside out, so the order matches `with()`.
