---
title: v1 to v2
description: Breaking changes introduced in version 2.0.0 and how to upgrade.
---

Version 2.0.0 replaces `hasOne` and `hasMany` with one [`relation`](/guide/relationships) decorator, replaces `map` and `mapper` with [`fromArray` and named mappers](/guide/mapping), drops `compose`, `fill` and `serialize`, and ships ES modules only. It adds [`Model.typed()`](/guide/typing), `Model.column` and `Model.relation`.

## Relationships

`hasOne` and `hasMany` still work, as deprecated aliases of `relation`.

:::code-group
```ts [v2]
@relation(() => Role)
declare role: Role | null

@relation(() => Comment, { many: true })
declare comments: Comment[]
```

```ts [v1]
@hasOne(() => Role)
declare role: Role | null

@hasMany(() => Comment)
declare comments: Comment[]
```
:::

`null` and `undefined` still become `null`, or an empty array with `many`. A one-to-one relationship no longer takes the first item when the data is an array, and a one-to-many relationship no longer wraps a single object in an array.

## Mapping

`map` and `mapper` are removed. `fromJSON` stays and returns `null` for `null` and `undefined`, as `map` did, so most `map()` calls become `fromJSON()`.

| v1 | v2 |
| --- | --- |
| `User.map(data)` with an object or `null` | `User.fromJSON(data)` |
| `User.map(data)` with an array | `User.fromArray(data)` |
| `User.map(data, true)` | `User.fromArray(data)`, after wrapping a single object yourself |
| `User.map(data, false)` | `User.fromJSON(data)` |
| `User.mapper('array')` | `User.mapperArray()` |
| `User.mapper('model')`, `User.mapper('nullable')` | `User.mapperJSON()` |

## Composition

`compose` is removed. Apply mixins by wrapping the class; the mixins stay the same, typed with `NormalizedModel`. Mixins apply from the inside out, so the order matches `with()`.

:::code-group
```ts [v2]
class Post extends SoftDeletes(Timestamps(Model)) {}
```

```ts [v1]
class Post extends compose(Model).with(Timestamps, SoftDeletes) {}
```
:::

## Instance Methods

`fill` is removed, as `merge` does the same. `serialize` is removed: call `toJSON()`, and override `toJSON()` for custom serialization. `$attributes`, which was always empty, is removed.

:::code-group
```ts [v2]
user.merge(values)
const data = user.toJSON()
```

```ts [v1]
user.fill(values)
const data = user.serialize()
```
:::

## Getters and Dates

Data for a property that only has a getter on the model is skipped. In v1, assigning it threw a `TypeError`.

`column.date()` reads `YYYY-MM-DD` as midnight in local time. In v1 it read it as UTC midnight, which is the day before west of UTC.

## ES Modules

The package no longer ships a CommonJS build, and needs Node.js 20 or later. Code that uses `require('@outloud/model')` needs to import it instead.
